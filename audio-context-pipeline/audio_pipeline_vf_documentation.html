Audio event classification, final ResNet34 selection, and local runtime integration.

This page documents the completed audio work in this folder. 03 / End-To-End Flow

Audio Pipeline Flow

1Data Collection And Preprocessing
Raw audio sourcesESC-50, UrbanSound8K, RAVDESS, CREMA-D, gunshot audio, siren audio, baby-cry corpus, and music/background audio.
DeduplicationFiles are audited and deduplicated before split. The dataset audit records raw counts, deduplicated counts, capped counts, and final split counts.
AugmentationTraining-only augmentation is used for minority targets. The final notebook augments glass_break, baby_cry, and gunshot.
Normalization and splitAudio is processed at 32 kHz, represented as log-mel spectrograms, resized to 224 x 224, and split with a 70 / 15 / 15 stratified rule.
2Modeling Objective: Six-Class Audio Event Classification

Branch A: Scratch CNN Baseline

Custom CNNFour convolution blocks with BatchNorm, ReLU, pooling, adaptive average pooling, dropout, and fully connected layers.
Training setupScratch phase, AdamW optimizer, cosine scheduler, weight decay, weighted cross-entropy, label smoothing, and MixUp.
OutputReference baseline for comparison against pretrained branches.

Branch B: Pretrained Candidate Models

Candidate backbonesResNet34 spectrogram, MobileNetV3-Small spectrogram, EfficientNet-B0 spectrogram, and PANNs Cnn14 waveform model.
Transfer learning strategyFrozen phase followed by full fine-tuning where supported. PANNs uses its waveform backbone with a custom classification head.
OutputThe comparison leaderboard selects final_vf_resnet34 for the later full training notebook.
3Explainability And Reliability Artifacts
Grad-CAMSpectrogram saliency overlays for the final ResNet34 class examples.
LIME-style attributionTime-frequency perturbation maps for local evidence in spectrogram decisions.
Waveform occlusionComparison notebook output records waveform occlusion for the PANNs candidate branch.
CalibrationTemperature scaling, expected calibration error, confidence histogram, and calibration curve are exported in the final run.
4Evaluation And Model Comparison
Leaderboard metricsAccuracy, macro F1, weighted F1, macro precision, macro recall, AUC macro OVR, ECE, latency, parameter count, and model size.
Final model metricsFinal ResNet34 metrics are exported as final_metrics.json, final_metrics.csv, and resnet34_final_metrics.json.
Evaluation visualsDataset split, learning curve, confusion matrix, calibration curve, and final score summary are saved in the final output folder.
Per-class outputsPer-class precision, recall, F1, support, macro averages, weighted averages, and top confusions are exported as CSV files.
5Integration With Runtime Backend
Exported checkpointresnet34_final.pt is the model used by the local runtime pipeline.
Runtime inferenceThe pipeline loads audio, creates 3-second windows with 1.5-second hop, converts each window to a log-mel spectrogram, and applies the ResNet34 model.
Context fieldsEach segment receives event probabilities, confidence, secondary events, acoustic features, integrity flags, and optional context module outputs.
API outputThe Gradio and FastAPI app returns the same structured JSON timeline for browser use or backend integration.

09 / Runtime Context Modules

Whisper, Hugging Face, Speaker, And Integrity Details

The runtime pipeline contains the final ResNet34 event classifier plus context modules that are controlled by the demo UI and API flags. The classifier runs for every segment. Voice and context modules run only when enabled and relevant to the segment.

Whisper transcriptionFor human_voice segments with sufficient duration, the pipeline can load Whisper tiny, base, or small. The output stores transcript text, language, and transcript status per segment.
Hugging Face emotionWhen enabled for voice segments, the pipeline calls superb/wav2vec2-large-superb-er and stores the top audio-classification predictions under hf_emotion.
Hugging Face deepfake screenWhen enabled for voice segments, the pipeline calls Vansh180/deepfake-audio-wav2vec2 and stores the returned synthetic-voice screening predictions under hf_deepfake.
pyannote diarizationThe optional diarization model is pyannote/speaker-diarization-3.1. It uses the configured Hugging Face token and assigns speaker labels to overlapping voice segments.
Local speaker groupingThe local fallback groups voice segments with acoustic speaker embeddings and the configured speaker threshold. Segment fields can include speaker_1, speaker_2, and later groups.
Reference speaker matchingWhen a prototype folder is provided, the pipeline builds local reference embeddings from audio files and stores the nearest reference speaker with match or weak-match status.
Acoustic featuresEach segment stores RMS, peak, zero-crossing rate, spectral centroid, spectral flatness, and spectral rolloff.
Acoustic context labelsEvents are mapped to context labels such as high_alert, distress_signal, speech_context, high_arousal_voice, and ambient_context.
Integrity screenThe clip-level screen records SNR, peak, RMS, clipping ratio, status, and issues such as clipping, low SNR, very low energy, short audio, or silence.

10 / Runtime Schema

How The Exported Model Is Used In The Pipeline

The runtime class in project/pipeline.py loads the exported ResNet34 checkpoint, applies the same class list, reads calibration settings from the checkpoint or metrics files, and returns a structured timeline for each uploaded audio file.

AudioContextPipeline.analyze(audio_path)
file: uploaded file name
file_hash: SHA-256 hash
duration_seconds: total clip duration
sample_rate: 32000
model: name, classes, checkpoint path, temperature, TTA shifts, metrics
summary: top event, clip probability, event counts, class confidence means, module status
integrity: SNR, peak, RMS, clipping ratio, review flags
timeline[]: per-window event label, confidence, probabilities, secondary events, features, optional transcript and speaker fields
xai_references[]: matching final XAI artifacts by detected class
elapsed_seconds: runtime duration

Runtime Decision Logic

  • Audio is loaded and resampled to 32 kHz mono.
  • Segments use 3.0 second windows and 1.5 second hop.
  • Each segment is converted to a 96-bin log-mel spectrogram and resized to 224 x 224.
  • ResNet34 probabilities are averaged across TTA shifts.
  • Close secondary predictions are exposed through decision_status and secondary_events.
  • Voice segments can receive Whisper transcription and optional speaker or Hugging Face context module outputs.
