03 / Model Lineup

Full model tree and subtrees

The key design point is that the document is decomposed before model routing. Page previews, embedded images, figures, signatures, handwriting, and unknown visual regions can call all four CNN models. Native text, tables, lists, and titles remain text-first unless the configuration explicitly enables CNN use on text regions. CNN1 supplies the content route; CNN2, CNN3, and CNN4 attach evidence role, readability, and authenticity labels. Fusion sends one clean document context to retrieval and reporting.

05 / Final Training Notebook

How the final production notebook is organized

Data controls

Label mapping, class caps, deduplication, train/validation/test split, and task-safe augmentation reduce leakage and imbalance.

Transfer learning

Pretrained backbones are trained in a frozen phase, then fully fine-tuned with smaller backbone learning rates.

Reliability layer

EMA comparison, temperature scaling, validation-only decision tuning, and calibration metrics are included before export.

Training strategy

Normalize files

Standardize PDF, image, office, and structured input handling before model training and downstream JSON assembly.

Frozen phase

Lock pretrained features and train the new classification head first.

Full fine-tune

Unfreeze the backbone with a smaller learning rate than the head.

Regularize

Use AdamW, weight decay, dropout, class weighting, label smoothing, safe MixUp/CutMix, and early stopping.

Calibrate

Fit temperature scaling on validation logits to improve confidence reliability.

Tune decisions

Use validation-only threshold or logit-bias tuning, then keep the method only if it improves validation F1.

Assemble pipeline

Define layout detection, captioning, text extraction, color and similarity checks, JSON assembly, and the end-to-end pipeline orchestrator.

Export

Save checkpoints, model card, comparison files, learning curves, confusion matrices, calibration plots, local explanations, and integration schema.

08 / RAG And Legal Feedback

How legal grounding works

Local legal library

Legal references live in project/storage/law_knowledge/. The current library covers Tunisia Law No. 58 of 2017, a case-triage checklist, international framework material, and U.S. VAWA reference material.

Retrieval index

The app chunks legal references, builds a local TF-IDF index by default, optionally adds FAISS sentence embeddings, and returns ranked cited chunks for the answer.

Scope routing

The query guard identifies Tunisia, U.S. federal, international, document-only, blocked, or general scope. Retrieval expansion and source prioritization follow that scope.

Guarded output

The final report avoids unsupported article numbers, unsupported codes, unrelated answers, prompt-injection requests, and legal overclaims. If Ollama is unavailable, a deterministic cited fallback report is returned.

13 / Reliability Boundaries

What the system can and cannot claim

Reliable for

Structured document context, evidence type separation, scan-quality labeling, authenticity screening, visual explainability artifacts, and local retrieval input.

Not a replacement for

Legal counsel, forensic lab verification, court admissibility decisions, jurisdiction-specific deadlines, or proof that an allegation is true.

Interpretation rule: model scores describe held-out visual classification performance. Legal decisions still require current law, verified facts, and qualified human review.
